03 // THE G.O.D. FRAMEWORK

We do not form teams randomly. We engineer them based on psychometric archetypes using the G.O.D. Framework (Generator / Operator / Destroyer).

GENERATOR (The Visionary) 1 PER POD

Core Function: Creates from nothing, sets North Star vision.

Responsibilities:
  • Idea generation & strategy
  • Creative direction
  • Problem framing
Strengths:
  • High-level thinking
  • Pattern recognition
  • Vision casting
Red Flags:
  • Over-promising
  • Scope creep
  • Refusing feedback
Success Metrics:
  • Vision clarity
  • Team alignment
  • Iteration speed
OPERATOR (The Builder) 2 PER POD

Core Function: Executes and ships, translates vision to reality.

Responsibilities:
  • Implementation
  • Task management
  • Shipping code/content
Strengths:
  • Execution discipline
  • Systems thinking
  • Deadline management
Red Flags:
  • Burnout risk
  • Over-commitment
  • Quality compromise
Success Metrics:
  • Velocity
  • Output consistency
  • Team satisfaction
DESTROYER (The Validator) 1 PER POD

Core Function: Tests, pivots, ensures market fit.

Responsibilities:
  • Critical analysis
  • User testing
  • Quality control
Strengths:
  • Objective evaluation
  • User empathy
  • Pattern spotting
Red Flags:
  • Negativity spiral
  • Blocking progress
  • Perfectionism
Success Metrics:
  • Quality improvements
  • User satisfaction
  • Iteration effectiveness
THE 1:2:1 RATIO IS NON-NEGOTIABLE.
1 Generator + 2 Operators + 1 Destroyer = The Minimum Viable Startup.
This structure prevents "Fractured Polymath" syndrome and ensures balance between vision, execution, and validation.

04 // POD STRUCTURE & LIFECYCLE

POD FORMATION PROTOCOL

  • Day 1: 363 Diagnostic administered.
  • Algorithm: Roles assigned based on diagnostic results.
  • Naming: [Cohort]-[Number] (e.g., "ALPHA-01", "BETA-07").

POD LIFECYCLE STAGES

  1. Formation (Days 1-7): Role assignment, kickoff, first standup.

  3. Validation (Day 30): Kill Switch checkpoint, portfolio review.
  4. Scale (Days 31-75): Iteration, user testing, revenue pursuit.
  5. Ascension (Days 76-90): Equity finalization, POD autonomy decision.

06 // COORDINAPE PROTOCOL

Proof of Contribution. We do not split equity equally. We split it based on value created.

HOW IT WORKS

  • Activation: Day 30 (after first Kill Switch checkpoint).
  • Tokens: Each member gets 100 GIVE tokens weekly.
  • Allocation: Give to teammates based on contribution. Cannot give to self.
  • Reset: Tokens expire weekly. Use it or lose it.

CONTRIBUTION CATEGORIES

  • Execution: Shipped features, completed tasks.
  • Support: Unblocking teammates, problem-solving.
  • Quality: Bug fixes, UX, polish.
  • Leadership: Coordination, morale, comms.
  • Innovation: New ideas, creative solutions.

07 // KILL SWITCH PROTOCOL

PURPOSE: Dissolve underperforming PODs with grace. We do not let teams die slowly.

CHECKPOINTS: Day 30 | Day 60 | Day 75

EVALUATION CRITERIA

Metric Green (Continue) Yellow (Warning) Red (TRIGGER KILL)
Velocity 3+ outputs/week 1-2 outputs/week 0 outputs / stalled
Team Health High morale Tension but functional Toxic / Ghosting
User Feedback Positive signals Mixed / Slow None / Negative
Revenue $1K+ or strong pipeline $100-$999 $0 / No path

DISSOLUTION EXECUTION

  1. Trigger: Facilitator flags Red status.
  2. Review: Full POD presents status/blockers.
  3. Decision: Continue / Warning / Dissolve.
  4. Dissolution (If Red):
    • Talent: Operators/Destroyers redistributed to active PODs.
    • Generators: 1-on-1 coaching, solo track, or exit.
    • IP: Archived to Pattern Library (100% Imaginarium).

08 // IP CLAUSE ENFORCEMENT

THE 80/20 RULE: 80% to POD Members (via Coordinape) / 20% to Imaginarium Liquidity Pool.

SCOPE

COVERS: Code, prompts, workflows, SaaS MVPs, agents, marketing assets created during the 90 days.

EXCLUDES: Pre-existing IP, post-graduation IP, personal brand content.

ENFORCEMENT CHECKLIST

  • ✅ Day 1: Signed by all members.
  • ✅ Day 30: Inventory audit.
  • ✅ Day 60: Valuation discussion.
  • ✅ Day 90: Final distribution.
